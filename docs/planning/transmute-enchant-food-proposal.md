# 点金与附魔料理提案

状态：2026-09-05 已实现四道料理及各自图标。已有奶香与容量料理的平衡调整保留。全量数值与验收边界见 [鱼料理经济审视](../backend/fish-cuisine-economy-audit.md)。以下保留设计理由；实现差异明确标注。

## 当前模型

- 点金 `alchemy.transmute` 每个实际操作消耗一个物品。现有规则返还经济基准价值的 75%～95%，另有失败概率和幸运倍率。默认最低失败率 10%，高级 / 首领 / 隐藏规则为 12% / 15% / 18%。
- 耗时不只是固定 8 秒：`alchemyTransmuteDurationSeconds` 按稀有度和经济价值修正，目前规则理论范围为约 8～22.8 秒。
- 普通点金、精确批量点金与分桶离线批量点金有不同结算入口，新增奖励必须共享同一公式，不能只修改普通单次路径。
- 附魔是 `EnchantEquipmentAffix` 的即时事务，不在普通动作队列。先检查装备可用候选，再按兼容稀有度权重抽取；不能修改静态全局规则对象。
- 商店价格从数据库 `shop_offers` 读取，经济基准价值不是玩家最低可重复买入价。本轮未读取生产商店数据，不能据此宣称已经证明无套利。

## 提案一：蜜焰快手烤鱼

配方：欧鲢 `chub`、雅罗鱼 `dace`（均普通）各 1，甜花蜜 3、苔光孢子 1、煤炭 2。

接下来 N 次符合条件的点金，每次耗时固定为 1 秒。标准 N=20，具体食材无特殊变异最多 40，三变异顶配最多 80。只做次数型烤鱼，不用时间型加速，避免多助手无限扩大覆盖操作数。

```text
S = clamp(0.30 L + 0.70 W + 0.10 T, 0, 1)
N_size = 20 + 20 S²
N = min(80, floor(N_size × M) + (有棱彩 ? 8 : 0))
M = 去重后的闪光 1.50 × 棱彩 1.10 × 彩虹 1.10
```

自动制作只得到 20 次。体重更偏向耐用次数；特殊变异乘数同时提升次数，棱彩额外加 8 次。三变异顶配为 floor(40×1.815)+8=80。

1 秒是最终单次耗时，不再叠乘其他减时倍率，不能变为 0 秒。不提高成功率、幸运率、金币或经验的单次产量。失败仍消耗一次。动作开始时冻结耗时，吃料理不加速进行中的动作；跨角色共享次数。

## 提案二：曦蜜聚金烤鱼 / 鱼汤

配方：鲤鱼 `common_carp`、欧洲鲃 `barbel`（均罕见）各 1，曦光花蜜 3、牛奶 2、苔光孢子 1；烤鱼加煤炭 2，鱼汤加晨露 3。

| 项目 | 标准 | 优质无特殊变异 | 三变异顶配 |
| --- | ---: | ---: | ---: |
| 额外金币比例 | 4% | 6% | 10% |
| 烤鱼次数 | 12 | 24 | 50 |
| 鱼汤持续时间 | 10 分钟 | 10 分钟 | 25 分钟 |

比例和次数分别成长，不使用一个“品质倍率”统一改变所有参数：

```text
S_gold = clamp(0.65 L + 0.35 W + 0.10 T, 0, 1)
bonusRate = round4(min(0.10, (0.04 + 0.02 S_gold²) × M))
S_count = clamp(0.30 L + 0.70 W + 0.10 T, 0, 1)
N = min(50, floor((12 + 12 S_count²) × M) + (有棱彩 ? 7 : 0))
duration = 600 + (有彩虹 ? 900 : 0)
```

烤鱼的棱彩额外 7 次，使顶配 floor(24×1.815)+7=50；鱼汤不将乘数再次作用于持续时间。闪光主打强度，棱彩主打次数，彩虹主打鱼汤时长；各变异本身仍有倍率收益。小体型三变异不保证顶值。

奖励规则：仅点金成功时，额外金币 = floor(本次幸运倍率前的正常金币 × bonusRate)。额外金币不进入幸运倍率、不产生额外点金、不返还输入物品。每件输入独立向下取整，不能批量求和后一次取整产生拆单差异；失败不给奖励，但消耗一次符合条件的次数。

正常收益与额外金币分开记账、展示。烤鱼和鱼汤互斥。建议与一秒点金也互斥：玩家选择“更快处理库存”或“单位材料多赚一点”，不让 10 分钟增金因一秒点金扩大到 600 次甚至多助手并发收益。

### 金币安全边界

首批加成只对白名单点金输入生效。白名单需要通过完整金币循环检查，不以单纯“战利品 type”或“小比例”代替验证：

1. 检查 NPC 可重复购入、兑换、转换、合成，以及再点金的路径。没有人工审批的新规则默认不享受增金，普通点金仍按旧规则工作。
2. 按最大稳定 / 幸运、质量上限和实际最低购买成本，评估重复循环的期望净收益。稀有幸运单次赚到钱不是套利，长期可重复正收益才是要阻断的路径。
3. 除固定商店外，玩家市场价格不能保证有底价；不能承诺阻止玩家主动低价出售导致的价差。目标是防止系统提供无风险或长期正收益的货币循环。
4. 速点与增金互斥仅限制产币速率，不能替代上述循环检查。速点本身也会放大旧有套利路径，需要一并审计。
5. 奖励使用 checked integer arithmetic。边界包括低价物品额外金币为 0、大批量溢出、离线分块、重试，以及到期边界。

首批实际白名单为：无面猫面具、狼王獠牙、发光浆果核、裂兆印记、永冬魄晶、凝愿香核。构建器排除转换 / 制作产物，服务端每次开工读取 NPC 出售状态进行额外否决；未用本地价格冒充生产价格。

## 提案三：月璃双珍烤鱼

配方：莲纹锦鲤 `lotus_koi`、璃背箭鱼 `glassback_darter`（均史诗）各 1，月露 4、瓶装星光 1、煤炭 2。两尾史诗鱼已体现高级成本，不再强制消耗一份月华精粹来换取不足 1% 的传说概率增量。

接下来 1 次符合条件的附魔，史诗与传说的已有权重 ×(1+B)。B 标准 10%，优质无特殊变异最高 15%，三变异最高 25%。这里提高的是权重，不是直接给传说概率加 25%。仅制作烤鱼；所有鱼质量和变异都不增加这项高级效果的次数。

```text
S = clamp(0.75 L + 0.25 W + 0.10 T, 0, 1)
B = round4(min(0.25, (0.10 + 0.05 S²) × M))
```

先筛选当前装备 / 工具支持的候选稀有度，再调整史诗和传说已有的正权重，最后归一化。不新增工具不支持的神话、传说，不改变该稀有度内部属性数值范围、不提高附魔成功率、不指定词条。

图示原始权重对应的概率：

| 稀有度 | 无料理 | 标准 B=10% | 顶配 B=25% |
| --- | ---: | ---: | ---: |
| 罕见 | 60% | 59.29% | 58.25% |
| 稀有 | 28% | 27.67% | 27.18% |
| 史诗 | 8% | 8.70% | 9.71% |
| 传说 | 4% | 4.35% | 4.85% |

表格仅适用于该工具及这四种稀有度都存在合法候选的情况。其他附魔工具按自己的分布重新计算，前端必须显示当前实际概率。

若合法候选中没有可提升的高稀有度，或只剩高稀有度导致归一化后完全不变，则不匹配、不扣次数。只要该操作符合条件并实际执行，无论最终抽到什么或附魔是否失败，都消耗一次。预览、材料不足、非法装备和事务回滚不扣次数。

## 实现边界

- 新增两个业务适配器：点金适配器负责最终耗时 / 成功产金；附魔适配器负责合法候选权重。全局引擎只管理匹配、快照、互斥和次数，不认识食谱 ID。
- `lifetimeScaling.charges` 复用质量计算原语，将制作结果冻结为已有 `lifetime.charges`；不把次数伪装成普通效果参数。每个配方独立定义 min/max、尺寸权重和变异次数奖励。
- 点金必须先取得“实际开始”效果快照，再确定该次耗时，不能队列入列时一次性冻结整队列。离线按次数耗尽、时间过期、跨角色竞争边界分段；无效果仍走现有批处理，不为所有操作强制逐件结算。保留现有快进步数 / 时间预算。
- 实现采用更窄的路径：有相关效果时逐次开工与结算，共用唯一的单件额外金币公式；无效果才保留原精确 / 分桶批量路径。没有向旧批量算法注入一份可重复使用的料理快照，不要求原近似随机与逐件抽样逐币一致。
- 附魔没有离线队列可接，直接在原即时事务中使用统一效果会话，遵循用户锁与装备锁的一致顺序。成功提交与扣次数原子化；同时审查命令重试幂等，不复用“队列提交就是开始”的假设。
- 当前附魔只允许玩家执行，因此不声称猫咪已有附魔入口。受益对象配置仍可扩展；点金照常对玩家和猫咪共享。
- 前端继续使用全局效果缓存。点金时间旁显示“原耗时 → 1 秒”，金币旁区分普通收益与料理额外金币；附魔稀有度权重旁给出“原概率 → 当前概率”。全部为只读预览，不负责资格、扣次或随机抽取。
- 已接入实际点金与附魔逻辑；不新增数据库结构。四个 128px 透明图标位于 `web/public/assets/icons/item/`：`honeyflame_quick_grill.png`、`sunhoney_gold_grill.png`、`sunhoney_gold_soup.png`、`moonglass_dual_fish_grill.png`。

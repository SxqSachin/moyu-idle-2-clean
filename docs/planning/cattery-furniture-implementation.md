# 猫舍家具实现与发布说明

运行时读取与生效时序已由 [统一缓存实现](cattery-furniture-cache.md) 更新：来源采用本地租约缓存，变更延迟生效。下文保留首版记录。

日期：2026-09-06。本文是 V1 实现记录；当前六级配方、5%..15% 寻宝概率、升级补差、贡献报告及迁移顺序以 [V2 实现说明](cattery-furniture-v2-implementation.md) 为准。没有在现有游戏库执行迁移。

## 首版玩法

| 家具 | 效果 | 安置材料 | 每份补给 |
| --- | --- | --- | --- |
| 猫咪书桌 | 猫咪适用工作经验额外分享 15% 给主人 | 木材 80、亚麻纤维 40 | 木材 20、亚麻纤维 40 |
| 寻宝柜 | 每只合格参战猫咪每个获胜波次有 20% 概率独立参加普通掉落判定 | 木材 120、铁矿 80 | 木材 30、铁矿 40 |

两件均限装一件，最多 120000 秒服务，每份补给 36000 秒。安置包含满额服务，初始暂停。启用按实际时间消耗，包括闲置和离线；暂停保留余量，不会自动扣库存续费。材料与概率是首版参数，尚未做生产经济平衡验收。

书桌源经验在既有猫咪归属倍率之前取值，不修改全局倍率，不减少猫咪收益。采集/生产、鱼食制作、猫咪钓鱼已接入；不扩展强化、炼金、建造、委托、战斗经验。经验按现有四位小数入账，每玩家每属性持久化整数余数，分片不丢零头。

寻宝柜额外轮次可能抽不到物品；仅使用本波合格敌人的普通 Drops，不复制主人已中奖的物品袋，不涉及公共波次奖励、首通、迷雾、试炼或经验。召唤物不算猫咪，已有奖励资格规则继续生效。所得加入既有 rewardPlan，明细不是第二条发奖命令。

## DSL 与扩展

权威文件是 `packages/game-data/source/json/cattery_furniture.json`，使用现有构建器生成服务端数据、前端类型、分块和图集。顶层为 `{"version":1,"cattery_furniture":[...]}`，单件示例：

```json
{
  "id": "study_desk",
  "version": "study-desk-v1",
  "nameKey": "game.furniture.studyDesk",
  "iconId": "item.study_desk",
  "installCosts": { "wood": 80, "flax_fiber": 40 },
  "refillCosts": { "wood": 20, "flax_fiber": 40 },
  "capacitySeconds": 120000,
  "refillSeconds": 36000,
  "rules": [
    { "kind": "owner_experience", "domain": "life_action", "rateBps": 1500 },
    { "kind": "owner_experience", "domain": "fishing_cast", "rateBps": 1500 }
  ]
}
```

支持原语为 `owner_experience` + `life_action/fishing_cast`，以及 `kitty_extra_loot` + `battle_reward`。`rateBps` 为 0..10000 整数。同一次操作的同类效果取最高值，不相加；同强度按稳定来源 ID 归属。不同领域、不同原语可以组合。

经验规则可带 `selector`：`actionIds`、`mainTypes`、`subTypes` 数组，同字段内为或，不同字段间为且。构建器验证引用。钓鱼有动作 ID，但没有通用采集/生产分类；添加不匹配的分类不会凭空生效。战利品原语首版不接受 selector。

上限：32 件定义，每件 8 条规则，每种成本 8 种材料，每个选择器字段 64 项，服务容量 7 天。未知字段、未知原语、非法比例、免费维护及无效材料在构建/加载边界拒绝。成本只接受启用的可堆叠非装备材料。

同机制新家具只增加数据、图标和翻译。新机制需要增加有类型的原语、校验、领域适配、展示与测试，不开放脚本、SQL 或任意事件写入。前端按原语/比例/选择范围分组显示，不按家具 ID 写分支。

## 领域边界

- `internal/catteryfurniture` 管定义、成本与服务时间投影。
- `internal/operationeffect/passive.go` 管纯区间匹配、开始快照、叠加和定点经验，不访问数据库，不伪装成食物次数。
- `internal/store/cattery_furniture.go` 管维护事务、库存账本、幂等请求和客户端投影。既有 EffectSession 在一次动作事务中加载和回写家具会话。
- `action_passive_effects.go` 管动作源经验、批量区间分段与玩家成长因果边界。钓鱼另以真实每竿开始冻结，不冻结整趟旅程。
- `battle_passive_effects.go` 在每场 run 创建时一次批量冻结成员来源，采用同一语句的 MVCC 可见性/时间戳，不引入反向用户锁。
- `battle_passive_rewards.go` 是无数据库访问的奖励适配，在原奖励与价值缩放结束后追加，不改原 RNGIndex，不把额外物品回灌原价值预算。
- 前端 service/store 统一管理请求、账号隔离、投影版本与未知结果恢复；猫舍组件管理交互。离线汇总明确分享经验已计入总量，战报按猫咪归属展示额外物品。

战斗额外随机键包含 run、波次、主人、猫咪、来源、阶段、敌人实例和物品。冻结来源保留在 run 状态、compileInput、playback checkpoint；重试不重新查询当前家具或随机发奖。

## 事务与离线

修改沿用用户事务锁，校验 requestId、revision、定义版本、库存和容量。材料、余额、区间、回执同事务提交；任一材料不足全部回滚。同请求只扣一次，同 ID 不同参数拒绝，重复启用/暂停不制造新区间。

安装/补给消耗库存前检查历史恢复是否完成；未完成返回 `FURNITURE_RECOVERY_PENDING`，不拿当前库存改写过去。暂停无需等待。服务区间为 `[from, until)`，新增服务只从当前开始；旧快照缺失视为无新增效果，不追授。已开始操作在暂停/耗尽后仍按冻结规则结算。

在线和离线使用同一执行器/会话。重复等价工作按服务边界分段代数计算，不逐动作查家具。存在可分享经验的猫咪运行或待执行队列时，猫咪批次不能越过玩家下一次完成，玩家重新计算下一次开始参数；同刻事件保留原队列排序。完成队列的后继按历史时间立即接续，防止未来经验倒灌。

保留既有 FastForwardBudget、检查点、hasMoreDue 和事务边界。没有第二个家具离线 worker，没有按离线时长再次补抽战利品。

## 数据与发布

新增四表：`player_cattery_furniture_state`、`player_cattery_furniture`、`player_cattery_furniture_periods`、`player_cattery_furniture_commands`。已付款定义冻结在实例中；旧余额未耗尽时禁止追加不同版本补给，耗尽后的下一份采用新定义。效果/成本/容量调整必须更新 version。

不要直接删除已发行家具 ID，目前没有退役/回收补偿接口，删目录会使旧实例不可操作。新退役机制需要专门设计。历史区间只在维护事务中清理，仅删除所有运行队列开始之前的部分，在途操作已有快照。每用户最多 4096 区间，达到上限仍可暂停；回执至少保留七天，旧 revision 不能重新成为扣款请求。

手工发布顺序：

1. 备份目标库，在维护窗口暂停写请求和动作/战斗相关 worker，避免混跑旧快照消费者。
2. 人工执行 `server/schema/migrations/20260906_cattery_furniture.sql`。不要对已有库执行 init.sql。本次开发未执行此迁移。
3. 部署相同版本 server、action-worker、battle-worker、settlement-worker 及相关服务，发布配套 game-data/前端。新代码启动前必须已有新表，服务不自动迁移。
4. 核查 readiness、日志、结构后恢复服务；用测试账号验收真实队列、参战、断线、重启和并发。
5. 产生新快照后不能直接回滚旧 worker 或删表。紧急时先停写、暂停未来服务，保留历史和奖励计划，使用兼容快照的修复版本恢复。

## 性能与验证

不宣称额外数据库成本为零。无安装用户复用原队列读取附带 EXISTS 检查，保持空效果快路径；有家具的动作事务增加一次有界来源批量读取，仅在分享余数变化时回写一次。每场战斗创建增加一次成员来源读取，回合/播放 tick/奖励入账不逐家具查询。UI 材料一次聚合读取，无逐材料查询。没有后台定时扣款。

M4 Pro 纯计算基准：100000 次相同经验代数分享约 363 ns/批、512 B、4 次分配；这不是数据库吞吐或全服容量指标。多队列为了成长因果会缩小批次，仍受原预算限制，需要生产并发压测。

已验证：DSL 构建；operationeffect/catteryfurniture/store/httpapi 关联包测试；前端定向测试、类型检查和生产构建。PostgreSQL 连接级临时表验证扣款幂等、跨材料回滚、历史恢复阻断、精度回写、来源隔离/冻结，以及通用执行器在线逐次、离线一次、7/13 次分片下 100 次操作都获得 3.5183 分享经验和相同库存。

另有钓鱼每竿快照/到期、同刻跨队列边界、战斗资格/原奖励/独立随机测试。浏览器验证的是隔离网络下真实 Vue 组件的桌面/手机与操作流程，不是真实账号 E2E。

尚未在已迁移真实环境完成多队列调度、长时间战斗、跨进程并发、重启的完整 E2E，也未完成生产压力/经济验收。全量测试不是全绿：Go catalog 专精版本断言失败；前端 cuisine 分组、鱼食配方和更新日志有六个断言失败，未为通过这些测试改动相应模块。构建保留大分块与 geetest directive 警告。

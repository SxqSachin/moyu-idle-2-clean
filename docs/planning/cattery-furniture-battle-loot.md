# 猫舍两件家具：书桌与战利品柜

状态：历史设计草案。2026-09-06 用户已授权实现；实际契约与发布步骤见 [实现说明](cattery-furniture-implementation.md)。下文保留设计阶段措辞与示意 DSL，不代表当前实现状态。

本文补充 [猫舍家具系统设计](cattery-furniture-system.md)。用户本轮确定：设计两件家具，第一件提供 15% 干活经验给玩家，第二件让战斗猫咪概率参与战利品分配。本文提出第二件的具体解释与参数，尚不代表用户已确认概率、适用范围或计费方式。

## 1. 两件家具的定位

| 家具 | 定位 | 核心收益 | 适用对象 |
| --- | --- | --- | --- |
| 书桌 `study_desk` | 记录工作心得 | 额外提供对应动作经验的 15% 给主人 | 执行适用生活动作、钓鱼的猫咪 |
| 战利品柜 `loot_cabinet`，暂名 | 整理探险所得 | 概率取得额外一次普通敌人掉落判定 | 本波实际参战且具有奖励资格的猫咪 |

书桌不是从猫咪身上扣经验；战利品柜不是从玩家和队友手上抢奖励。两件家具分别作用于生活经验与战斗物品，不互相触发，不让战斗战利品再产生书桌经验。

两件各限装一件，独立启停、独立维护池，共用同一设施 UI、维护服务、库存 ledger 和规则注册结构。是否按启用现实时间消耗沿用主文档的推荐方案，尚待玩法确认。

## 2. 书桌：15% 已确定

```text
书桌额外玩家经验 = 本次操作归属转换前的对应经验 × 0.15
```

例：猫咪伐木对应采集经验 2，主人额外获得采集经验 0.3。当前普通猫咪动作的玩家经验基础倍率为 0，不能在乘完 0 的结果上再乘 15%。猫咪钓鱼仍保留原来的钓鱼经验。

普通动作与钓鱼的范围、四位精度余数、开始快照、离线分片、跨角色经验因果等继续按主文档设计。强化另有既有经验规则，仍待单独确认；不分享战斗、委托、随记或技能书经验。

## 3. 战利品柜：推荐玩法

### 3.1 为什么推荐“额外资格”，不是瓜分

现场代码 `server/internal/httpapi/battle_runtime_engine.go` 的 `resolveBattleWaveSettlement` 表明：普通敌人掉落按玩家分别判定，波次公共掉落则房间判定一次并给予各玩家同样的结果；猫咪另有战斗经验，但没有同等的普通物品掉落轮次。这不是一份固定战利品在成员之间瓜分。

因此推荐把“参与分配”解释为：**猫咪有概率取得自己的额外普通掉落轮次，所得物品存入主人背包。** 保留原玩家奖励，不修改队友收益与分配方式，也不复制玩家已经抽到的奖励列表。

玩家文案建议：**每次战斗获胜，每只参战猫咪有 20% 概率额外搜集战利品，所得归主人。** 20% 是首轮平衡建议，不是已确认参数。详情明确“仅普通敌人掉落；取得资格后仍可能没有收获”。

### 3.2 触发与资格

| 项目 | 建议契约 |
| --- | --- |
| 判定单位 | 每只合格猫咪、每个获胜波次一次，不按回合、攻击次数或整次挂机会话 |
| 暂拟概率 | 20%，DSL 可调 |
| 成功后 | 对本波合格敌人的普通掉落表独立判定一轮，不保证必得，不再抽家具参与概率 |
| 接收者 | 该猫咪的主人，沿用库存入账，不增加猫咪背包 |
| 参战资格 | 本波开始时已在权威阵容中，具有稳定 kitty ID 和主人关系；结算时猫咪及主人仍满足现有奖励资格 |
| 是否要求存活 | 不额外要求；实际参战后阵亡但队伍获胜，且奖励资格有效，仍可参加，避免惩罚承担伤害的猫咪 |
| 主人原奖励 | 完全照旧；额外奖励不能降低它 |
| 失败、逃离、中断 | 不触发本波额外掉落；此前已合法结算的波次不受影响 |
| 排除对象 | 未参战猫咪、召唤物、幻影、临时分身，不凭单位名字识别 |

两只合格猫咪意味着两次独立 20% 判定，可能有零只、一只或两只触发；不是“整体 40% 保证触发”。每只最多取得一轮资格，不通过多家具叠加给同一猫咪重复轮次。

不设置“必须造成伤害”门槛，否则辅助猫咪容易被误排除。是否参战从权威阵容和奖励资格读取，不能通过打开家具页、客户端发消息或伤害统计推断。

### 3.3 掉落范围与倍率

首版只开放普通 PvE 的敌人普通掉落，使用已击败且原本可结算掉落的敌人实例集合。排除竞技场、战斗试炼、迷雾特殊模式；不扩展这些模式现有奖励契约。

掉落来源只包括敌人定义的普通 Drops，不包括波次公共奖励、自定义阵容专项奖励、难度特殊奖励、迷雾专属奖励、首通/任务奖励、保底次数、战斗经验和技能经验。普通敌人掉落表里本来就有的稀有物品不额外排除；按奖励来源分类，不能仅按物品类型猜测。

首版沿用主人本波普通掉落的难度、幸运和掉落加成计算上下文，来自本场权威战斗状态，不读取结算入账时的实时装备。猫咪自己的幸运与掉率暂不另建计算口径，避免首版同时引入一套掉落配装体系；未来若需要，以新版本明确增加受支持的 statSource。

额外判定复用现有普通掉落公式，每个敌人实例、每个掉落条目独立计算。不能把“主人本波没掉物品”当作猫咪无资格，也不能将主人抽到的成品实例复制一份。随机词条物品继续走合法生成路径，不复制实例 ID 或继承不属于本次生成的快照。

### 3.4 奖励缩放不能影响原收益

此节记录设计时的实现。现在普通掉落和猫咪额外掉落均使用配置数量，战斗经验也已移除按奖励总价值缩放的步骤。

现场代码在普通掉落、阵容掉落和房间波次掉落之后调用 `battleValueBucketScale`，且缩放同时影响原物品和经验；特殊难度奖励在之后独立添加。因此直接把猫咪额外物品插进原 scale 计算之前，可能降低玩家原收益。

推荐顺序：

1. 完整计算所有玩家的原奖励，原随机调用路径与原价值缩放不变，保留普通奖励计算上下文及原 scale。
2. 额外规则单独计算猫咪普通掉落，数量沿用原普通奖励的已算 scale 及取整规则，不把新增价值回灌重算原 scale，也不单独用小额猫咪奖励求出更高 scale。
3. 检查额外数量、总量和现有容量/经济约束，再把额外奖励追加到主人最终奖励计划中。若另有严格总额上限，应优先保留原奖励、仅限制额外部分，并在实现前确认策略，不悄悄突破或重分配。
4. 猫咪额外奖励独立标注来源，但只入账一次；展示摘要不是第二次发奖指令。

这是明确选择让家具增加普通掉落供给，而不是重新分摊原价值预算。现有价值缩放开启/关闭、极端倍率及稀有高价值产物必须分别经济核算，不能只验证函数能运行。

## 4. 维护与经济设计

书桌维护倾向消耗木材、纤维等生活材料；战利品柜倾向消耗木材、铁矿与适量普通怪物掉落材料，形成生活资源与战斗资源的长期消耗。怪物材料具体 ID、数量需选定后校验，不在草案里虚构现有物品。

首版不新增“战利品券”或“家具能源”中间货币。维护可直接扣用户确认的库存材料，配方不能默认使用稀有装备、技能书、独立实例或被预留的物品。

书桌的 100 容量、3/小时、30/份可作为共同交互模型的原型，但战利品柜的消耗速率与成本需独立核算，不能因为都叫家具就定同价。

设合格猫咪数为 N，每只参与概率为 p，各自一次合格普通掉落轮次的期望价值为 V_i，则额外掉落期望为 `sum(p * V_i)`；V_i 必须包含实际缩放、取整和上限，不等同于整场全部奖励价值。按相同普通掉落上下文粗估，两只猫、20% 概率相当于平均增加 0.4 个普通掉落轮次，不意味着所有战斗奖励增加 40%。

核算单猫、常用数量及现有参战上限，再结合每小时获胜波次、普通稀有掉落期望、库存流通及维护成本确定 p。固定按家具时间计费意味着多猫收益更高，这是需要主动接受的成长曲线，而不是计算漏洞。

## 5. DSL 与领域适配

家具仍放在同一 `cattery_furniture` 权威定义中，只引用不同规则。战利品柜规则语义示意如下，不是已经可加载的生产配置：

```json
{
  "id": "furniture.loot_cabinet.extra_loot",
  "rulesetVersion": "kitty-extra-loot-v1",
  "domain": "battle_reward",
  "kind": "battle_reward.kitty_extra_loot_roll",
  "params": {
    "participationChance": 0.20,
    "scope": "eligible_kitty_per_won_wave",
    "rewardPool": "normal_enemy_drops",
    "statSource": "owner_reward_context",
    "recipient": "owner",
    "requireSurvival": false,
    "stackGroup": "kitty_extra_loot_participation",
    "stackMode": "max"
  }
}
```

每个字段都是处理器支持的枚举或有界数值，不允许自由填事件、数据库字段或脚本。相同组多个授权时取最高概率，不加算重复资格；相同概率按稳定来源键选取，避免来源归属随遍历顺序变化。

新增 `battle_reward` 是一次独立领域接入，共享家具来源、规则注册、版本、有效区间和快照结构；战斗领域适配器接收有类型的参战阵容、原掉落上下文、已击败敌人及冻结规则，返回带来源的额外奖励计划，不访问数据库，不管理家具维护。

普通动作队列、动作离线规划器不增加战利品柜分支，战斗不会伪装成 life_action。后续同种战斗家具只改数据；新战斗奖励机制添加这个领域的处理器，不在战斗回合、播放 tick 和结算 worker 各写一份判断。

## 6. 战斗时序、离线与随机一致性

### 6.1 冻结边界是本场波次开始，不是结算时刻

本项目有预演编译、时间线回放、异步结算阶段，不能等发物品时才查“家具现在是否启用”。

- 本场 run 开始时，按权威开始时间冻结各主人的适用家具来源、规则版本、比例和合格猫咪阵容，并持久化到编译输入；不是在后台实际拿到 compile 槽时读取当前家具。
- 本场开始后补充/启用不追授本场；之后暂停或耗尽不撤销本场冻结资格，下一波重新判断。
- 跨波继承 HP/MP/装备状态不代表沿用旧家具资格。下一场只更新本领域快照，不趁机刷新已冻结的装备、专精或战斗属性。
- 不冻结整次无限挂机会话，否则短时间维护可以覆盖无限波次；也不按每个战斗回合重新扣维护或抽参与概率。
- 确定的额外奖励加入持久化 rewardPlan，回放和 settlement worker 只消费同一结果，不重新抽奖，不读取实时家具覆盖它。

场次启动读取多名玩家家具时，应批量获取必要来源，按现有房间、run、用户锁顺序设计事务，避免引入逆序死锁；实现前需核对具体启动事务，并证明并发暂停/启用与 run 开始有确定先后，不能用未验证的最终一致缓存决定付费效果。

### 6.2 独立随机序列

参与资格与额外掉落使用独立命名空间，不调用原战斗 `state.randFloat64` / `state.randInt`。种子与抽样键包含持久化 run 身份、波次、主人、猫咪、规则来源及抽样阶段；掉落再区分敌人生成实例、物品/条目及数量/词条阶段。

敌人不能只用模板 ID，因为同波可以有多个相同敌人；重编译同一 run、重放时间线、结算重试均不得换种子。参与与掉落分别派生，不让“多一个掉落条目”改变参与判定。增加或移除家具不改变原战斗伤害、原掉落和队友随机结果。

### 6.3 离线不再跑第二遍战斗奖励

离线动作快进只处理书桌在生活动作中的规则；后台战斗由既有战斗启动、编译、回放和结算体系推进，离线玩家奖励资格与时长上限保持原规则。不能在玩家登录时根据离线时长再次补抽战利品柜。

若现有恢复路径需要重建未完成场次，继续读取本场已冻结输入与已有奖励计划；不能用恢复时的家具或装备状态重算本场。旧 run 没有战利品柜快照时额外结果为空，原奖励不变。

余量的现实时间投影与战斗回放/恢复进度分开；每波读取既有服务区间，不每波重复扣一整段离线维护量。没有符合资格的猫咪、参与概率为 0、模式不适用时，不遍历额外掉落表。

## 7. 奖励持久化与兼容

当前 `battle_settlement_manifest.go` / `battle_settlement_worker.go` 校验 rewardPlan 与主人/猫咪归属；本领域必须进入同一权威链路，不另开 HTTP 发奖接口。

最终 ItemRewards 包含原奖励与合法额外奖励，额外明细只记录来源与拆分，不能让 worker 根据明细再加一次。既有按 run/用户的领取、租约和事务幂等路径需验证包含新增物品；不能只依赖消息只送一次。

明细最少包含规则与版本、主人、猫咪、来源家具、是否取得资格和实际物品汇总。体积按参战猫咪数和唯一物品数约束，不把每次未命中掉落都展开到完整战斗 timeline。原随机结果的稳定输入保留在冻结记录中以便诊断。

冷存储、精简结算 manifest、历史战报摘要都要保留足够的版本与来源，不能只改完整 final result 而在压缩路径丢失。读取新版本时校验来源、归属、合法模式、数量及总量；损坏数据进入既有隔离/重试机制，不静默漏发或用当前家具补算。

发布时相关 server、battle worker、settlement worker 都需能读取新结构，再启用家具定义。未知 battle_reward kind 或不支持的模式不能在配置中启用。旧战报不补造猫咪贡献，也不把它展示成过去已经参与过。

## 8. 前端体验

猫舍家具标签展示两条同构设施内容，书桌标记“工作”，战利品柜标记“战斗”；不增加只有两个项目的复杂筛选。图标分别表达书桌与整理战利品的柜子，复用现有游戏美术风格。

战利品柜主信息：每猫每胜利波次的参与概率、仅普通敌人掉落、全部合格参战猫咪、维护量和剩余服务时间。不能写成“掉落率 +20%”或“20% 必得战利品”。

开关、补充确认、份数、材料缺口、请求结果未知、暂停不停历史结算等交互复用主文档，不为第二件家具复制服务状态管理。

战报显示“猫咪额外战利品”，按猫咪列出触发和实际所得；触发但空掉落显示“参与搜集，本次无收获”，没触发显示“本次未触发”或折叠摘要，不能都记成“失败”。胜利 summary 可显示总触发猫咪数与实际奖励，详细名单按需展开，不每猫弹 toast。

当前波次显示已冻结的资格，猫舍开关显示未来服务状态，两者可以不同。例如“已暂停；本场已开始的效果仍保留”属于真实游戏规则，不显示 DSL/快照等实现词汇。后续波次是否启用以服务器新场次状态为准。

## 9. 验收与待确认

额外验收至少包括：

- 书桌 15% 文案、DSL、原始经验和离线结果一致；战利品柜不带来额外战斗经验。
- 每猫每波仅一次资格判定；同模板多猫、同模板多敌人、阵亡辅助猫咪、召唤物均按身份正确处理。
- 获胜/失败/中断、模式排除、猫咪与主人奖励资格、离线时长上限正确，不因家具绕过。
- 概率 0/1 和中间值正确；触发后空掉落可解释；多猫判定独立且重试可重现。
- 没有家具与有家具两次同种子执行，剥离额外物品后原奖励、战斗过程及队友奖励完全相同。
- 价值缩放开关、极端掉率、数量溢出、稀有产物与词条实例生成，均不降低原收益或复制非法实例。
- 本场开始/耗尽/暂停/补充边界及下一波重新冻结准确；编译排队延迟不改变资格。
- 编译重试、回放重连、结算重试、冷摘要恢复不重抽不重发；不同 worker 版本不能静默丢字段。
- 家具读取按场次/房间必要来源批量执行，回合与播放 tick 零家具查询；未触发资格不遍历额外掉落表。

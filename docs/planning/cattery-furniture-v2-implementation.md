# 猫舍家具 V2 实现、经济核算与发布

2026-09-06。已实现代码和生成数据，未执行正式数据库迁移。本文覆盖 V1 文档中的概率、成本和展示方案。

这里的成本参考值是 `quantity * item.economyBaseValue` 的和，不是另扣金币，也不是实际市场成交价。寻宝是参与概率，参与后仍按普通敌人掉落判定，可能空手；不复制已中奖奖励、不瓜分队友所得、不影响原 RNG。

两件家具各限一件，安置含 33 小时 20 分钟预付时间，初始暂停；每份补充 10 小时。启用后现实时间、闲置和离线均消耗预付时间，暂停保留余量，无自动库存扣款或续费。所有猫咪共用一件家具的时间，不逐猫增加维护扣款。

建造使用木坯而不是原矿，铜铁承担包角、铰链及抽屉机构；纤维与软脂承担装订、保养；柜子的膜、芯片承担衬垫与寻宝机构。高级木材/金属逐级加入；书桌加入冰霜魔法卷轴，柜子加入冰霜碎片、暗影丝、魔像暗核。未使用仅看 rarity 似乎低级、实际来自高等级地图的星轨铜片或缄默墨晶。

## 为什么这样加量

相比上一份设计草案，安置各项材料提高至三倍，基础加固与主要升级材料也提高至三倍；书桌基础维护参考值由 1,468 提高至 3,883，柜子由 1,683 提高至 2,525。高等级木材维护追加没有再机械乘三，避免微小经验提升绑定过高维护。

数据中的基础动作：木材 16 秒/个，亚麻纤维 12 秒/个，软脂 32 秒/个；铜锭还需 4 铜矿、3 煤、4 石，铁锭需 4 铁矿、3 煤、4 石。书桌每 10h 的木材、纤维、软脂部分，未计任何加速就需要约 41.6 分钟采集，另有采矿与加工，因此不是“只需几份金属”的无成本加成。坯料也有原料与加工时间。

一次性安置参考值：书桌 21,792，柜子 36,666。升级参考值如下，不含当前剩余预付时间的维护补差：

| 升至 | 书桌 | 柜子 |
| --- | --- | --- |
| 2 | 16,902 | 17,670 |
| 3 | 22,998 | 25,404 |
| 4 | 28,062 | 31,710 |
| 5 | 38,073 | 38,841 |
| 6 | 49,158 | 68,214 |

收益敏感性而非回本承诺：书桌一只猫连续有效工作 10h，在基础动作经验稳定时分享相当于该猫 1.5h/2h 的源经验；两猫为 3h/4h。若只有效工作 2h 却持续启用 10h，收益只有前者五分之一，维护不变。应主动暂停闲置家具。

柜子期望收益模型为 `胜利波数 * 合格参战猫数 * 参与概率 * 本波普通掉落期望值`，还受真实掉落加成、幸运、难度、价值桶缩放与整数取整影响。仅作敏感性例子：按 base_4 普通敌人未修正平均掉落参考值约 6.19、每波 5 敌、10h 胜利 600 波，Lv1 一猫约 929、两猫约 1,858，低于 2,525 维护；胜利 1,200 波则两猫约 3,716。不能在概率下调后继续无脑翻倍维护。Lv6 参与概率为 Lv1 三倍，维护参考值约 2.39 倍。

结论：主要加量落在安置/升级和低级原料回收，维护保留有意义但有限的常驻压力。低效、低掉落战斗不保证正收益，材料实际市场价值也不会被配置保证；没有据此伪造回本时间。上线后的真实交易与参与统计仍需观察，不额外加常驻采样 worker。

## DSL 和升级事务

权威文件 `packages/game-data/source/json/cattery_furniture.json`，顶层版本 2。根定义保存 Lv1；`levels` 声明 Lv2..6 的 `level / upgradeCosts / refillCostAdd / rules`。维护完整配方为基础加所有此前增量，所有增量必须正整数，最多 24 种。Lv6 书桌 14 种，柜子 17 种，不截断，也不替代低级材料。JS 构建器和 Go 运行时均严格校验。

`Definition.AtLevel` 在家具边界展开完整定义；生活动作、钓鱼、战斗只消费已有通用原语和不可变快照，不读取等级表、不识别书桌/柜子 ID。新家具调参只改 DSL、图标和翻译，新机制仍需强类型原语与测试。

升级报价是 30 秒有效的无状态指纹，绑定用户、revision、旧/新完整定义、升级配方、报价余量和到期时间。服务端确认时重新计算，不相信客户端提交的成本。每种补差为 `ceil(max(新维护每毫秒单价 - 已付旧维护每毫秒单价, 0) * 剩余毫秒)`，使用整数有理数。实际扣款不能超过展示上限；其他命令导致 revision 改变即拒绝，前端不能自动重新定价并重发。

升级与普通补给共用用户锁、恢复门禁、固定顺序库存锁、账本与 requestId 回执。一次性材料和补差原子扣除；不足、报价过期或状态冲突不部分升级、不部分扣费。未知响应重试原命令，包括已经过期但已成功的回执请求。保留剩余时间和启停状态，不能用低级耗材免费享用高级效果。

## 在线、离线与贡献

升级只关闭未来服务区间并添加新来源。已开始的动作、鱼竿、战斗和 checkpoint 不变；逻辑开始时间决定使用哪个版本。离线仍复用既有预算、冻结快照、开始时间排序和检查点，不逐家具增加快进循环。

`operationeffect.Contributions` 是已发奖励的归因，不是发奖入口。动作结算在已有经验读写中捕获实际接受的数量，达到经验上限的部分不计入家具贡献；原奖励优先占经验容量。无需额外属性查询。贡献与余数同一行、同一次既有 flush 提交，保留四位精度；在线与离线分片结果等价。

柜子贡献沿现有 rewardPlan / 编译状态 / 最终入账事务传递；验证物品归因不超过实际发奖，统计机会、命中、空手和实际物品。不扫描完整战报，不新增按猫/物品 INSERT。每个有家具贡献的玩家在现有结算事务中额外读写一行累计值，无家具玩家跳过。不是零开销，但无每秒维护写库、无额外 worker、无每个动作查家具或全量库存刷新轮询。

离线弹窗独立展示“家具贡献 · 自上次确认查看”，包含书桌经验和柜子战利品。这个窗口明确不同于本次动作快进，避免误导玩家把异步战斗结算当成同一时刻完成。已有总收益不再次相加。报告持久化 snapshot，显式确认只推进该 snapshot；报告打开后晚到的战斗收益进入下一份报告。断线重读、重复确认、旧 token 确认新报告、跨账号均有保护。升级前未记录的历史收益不伪造回填。

## UI

桌面为家具选择栏和单件详情，窄容器自动变横向选择、单列详情。维护材料始终展示，格式沿用 `QuickRefWithRequire` 的图标/名称/需求(库存)，不足有红色和文字缺口。补给满容量仍可看维护配方，缺料显示原因。支持数量步进和合并总材料确认。

升级显示当前到下级效果、一次性成本、剩余维护补差、合并总扣款、升级后的每份维护。打开后捕获报价，不静默替换；过期需要明确刷新。普通补给手机使用窗式弹窗；长升级使用滚动内容和固定确认栏。六种语言均已覆盖。贡献报告和家具页展示真实累计量，不显示预测收益为收入。

## 手工发布顺序

1. 备份数据库并停止旧 server、action-worker、battle-worker 等会写奖励的进程。
2. 若未装 V1，先人工执行 `server/schema/migrations/20260906_cattery_furniture.sql`。
3. 人工执行 `server/schema/migrations/20260906_cattery_furniture_v2.sql`，再部署同版 server/worker/前端/game-data。
4. 新建库的 init.sql 已包含新列。迁移不得让旧 worker 在更新后覆盖新的累计字段或继续生成旧概率来源。

V2 SQL 增加累计/已读/当前报告 JSONB。旧 V1 柜子未来参与概率从 20% 修正为 5%，迁移时切分服务窗口，保留原到期时间、维护已付款及历史快照；暂停的旧柜子也修正未来效果。保留独立 legacy 版本，因此旧廉价耗材不能继续补充。旧窗口过多会明确中止事务，先恢复历史工作再迁移。迁移可重复执行，已开始战斗不追溯重抽。

## 验证边界

- DSL 验证和数据构建通过；所有等级、概率、低级成本保留、非法升级数据有断言。
- Go 家具/通用效果/商店/HTTP 定向测试覆盖；8 项本机 PostgreSQL 临时表证明在线/离线分片、事务回滚、请求重放、运行升级边界、历史恢复门禁、经验上限、报告迟到收益及迁移幂等。测试只操作 pg_temp，没有正式迁移或真实库存变更。
- 前端家具/报告 11 项测试、类型检查和生产构建通过。真实 Vue 组件在隔离模拟数据页面检查桌面、390/320px 手机、完整 17 种维护材料、短缺和升级滚动弹窗。
- `BenchmarkPassiveRepeated` 在本机 M4 Pro 上，100,000 次同质操作的代数经验计算约 298ns / 1,024B / 8 次分配；这是纯函数级微基准，不是服务器吞吐或多 worker 压测结论。
- 全量前端现有 6 项失败位于 cuisine、fish-food 和 update-log，663 项通过；未借本任务重写这些配方或用户正在编辑的日志。Go 全量存在专精版本预期与当前 specialization-v6 不一致的失败。
- 浏览器验证不是已迁移数据库的登录玩家端到端验证；正式发布后的真实库存、断线/重启与多 worker 压测仍是发布验收边界，不能称为已全部证明。

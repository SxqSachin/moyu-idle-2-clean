# 游戏内容蓝图（架构设计阶段）

## 1. 目标
- 统一策划、前端、后端对“游戏主循环 + 系统边界 + 核心实体”的理解。
- 为后续数据库重构与协议收敛提供业务语义基线。

## 2. 玩法主循环
1. 登录/注册并绑定会话（HTTP JWT + WS bind）。
2. 进入动作循环（锻炼/劳作/战斗/制作）并通过动作队列持续推进。
3. 获取资源与物品，驱动装备成长（强化/修复/异变/附魔）。
4. 参与市场交易（玩家交易 + NPC 兜底市场），形成经济循环。
5. 完成日常委托并获取成长资源，增强后续动作效率。
6. 实时消息推送（队列进度、资源变更、系统消息）驱动前端状态更新。

## 3. 领域地图（Domain Map）
- 账号域：认证、玩家身份、基础资料。
- 角色成长域：基础属性、派生属性、活动状态。
- 库存装备域：堆叠物品、实例化装备、装备位、仓库布局。
- 动作调度域：动作目录、执行队列、属性经验结算、离线快进。
- 市场交易域：上架、购买、账本、手续费梯度、NPC 报价。
- 任务与日常域：模板池、任务刷新、任务提交结算。
- 实时通信域：WS 绑定、事件推送、聊天。
- 配置域：`packages/game-data` 单一数据源与版本一致性。

## 4. 核心实体（统一术语）
- 玩家（Player）：系统中所有资源与状态归属主体，主键 `user_id`。
- 物品模板（Item Template）：由 `packages/game-data` 定义的静态配置。
- 物品实例（Item Instance）：可成长装备实例，包含耐久、词缀、状态。
- 动作队列项（Action Queue Item）：可运行或排队动作单元，支持多次执行。
- 市场挂单（Listing）：卖方发布的可购买单据（堆叠或实例）。
- 市场订单（Order）：买方成交记录，包含手续费、卖家净收入与幂等键。
- 日常任务实例（Daily Task）：玩家当前可提交任务快照。
- 仓库布局项（Warehouse Slot）：实例物品在仓库中的坐标和占位信息。

## 5. 关键状态机
### 5.1 动作队列状态
- `pending -> running -> done`
- 异常路径：`running -> failed`（由事务失败、资源不足、配置缺失触发）

### 5.2 市场挂单状态
- `active -> sold_out | cancelled`
- 并发约束：交易链路必须在单事务内完成库存与资金结算。

### 5.3 日常任务状态
- `open -> completed`
- 刷新策略：固定窗口刷新，最多持有数量受上限控制。

## 6. 前后端边界
- 前端负责：页面编排、状态聚合、事件渲染、用户输入校验。
- 后端负责：事务一致性、并发控制、结算规则、最终状态判定。
- 协议契约：
  - HTTP：`{ ok, ts, data | error }`
  - WS：`{ type, ok, ts, data | error }`

## 7. 一致性与并发原则
- 同玩家关键链路串行化：动作推进、任务提交、活动切换。
- 跨玩家链路可并行：市场撮合、聊天、广播。
- 所有经济与库存变更必须具备幂等语义（请求幂等键 + 事务去重）。
- 缓存仅做性能层，数据库为最终一致性来源。

## 8. 性能与扩展基线
- 动作与战斗采用事件驱动推进，避免高频全量轮询。
- WS 仅发送增量 patch，避免大对象重复推送。
- 多实例模式下通过 NATS 同步跨节点事件。
- i18n 默认支持六语言（`zh-CN`/`zh-TW`/`en-US`/`ja`/`ko`/`ru`），Web/Electron 共享同一前端行为。

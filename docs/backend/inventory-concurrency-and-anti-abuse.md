# 库存并发与防刷设计

## 目标
- 在放置类高频读写下保持库存一致性，避免刷库存、重复扣减与重复发奖。
- 在多实例部署下保持仓库写入行为可预测、可审计、可回滚。

## 风险模型
- 并发写冲突：同一实例被同时移动/强化/上架。
- 重放写请求：网络重试导致重复执行。
- 可见性延迟：缓存与数据库状态短暂不一致。
- 边界绕过：客户端伪造坐标、数量、状态。

## 核心策略
1. **事务一致性**
   - 仓库入库/出库、装备成长、市场实例流转必须单事务完成。
   - 关键行使用 `FOR UPDATE`，保证同实例串行。
   - 可堆叠物品无论单件还是批量入库，都必须先尝试合并到现有可堆叠实例。
   - 不可堆叠物品即使来自批量结算（如动作队列快进）也必须逐件实例化入库（每行 `quantity=1`）。
   - 动作产物只要带有实例态（如 `enhanceLevel>0` 或 affix 非空），一律按实例物品处理，不允许数量合并。
2. **版本并发控制**
   - 仓库写入走 `expectedVersion + lock_version` 校验。
   - 冲突返回结构化错误码，前端刷新后重试。
3. **幂等约束**
    - 外部可重试写接口要求幂等键（尤其交易/结算类）。
    - 幂等记录落库并受唯一索引保护。
   - 受保护写路径必须拒绝非法数量（`qty <= 0`）而不是静默成功。
4. **防刷与防重复**
   - 发奖路径要有唯一消费标识（任务批次/结算键）。
   - 对高风险接口增加行为审计日志（用户、实例、前后状态、请求键）。
5. **缓存策略**
   - 读路径采用“HTTP 快照 + WS 增量”。
   - 写后失效缓存，避免陈旧视图引导错误重试。
6. **审计旁路**
   - 库存变更日志不得决定库存事务成败；库存扣减、发放、状态迁移提交成功后，再 best-effort 写入审计记录。
   - 审计记录采用 `category + direction + subject` 扩展模型，新增来源只注册分类与转换逻辑，不改库存真值写入。
   - 高频动作队列日志按队列任务和方向聚合，避免按每次 action 写入流水。

## 首批优化清单
- 减少全量扫描与锁范围，优先按 `user_id + instance_id` 精确锁定。
- 为高频查询补齐组合索引，降低库存读取放大。
- 提供批量操作信息读取接口，减少前端 N+1 请求。

## 可观测要求
- 记录：版本冲突率、事务重试率、库存写失败码、异常回滚次数。
- 告警：冲突率突增、重复写命中率突增、限流拒绝率异常。

## 当前实现评估（结论）
- **结论**：当前库存系统可支撑中等规模放置类读写（单实例到小规模多实例），但在高并发“同用户热点写”场景下，冲突率和锁等待会明显上升。
- **强项**：
  - 仓库写路径已有事务与版本冲突控制（`lock_version`）。
  - 关键放置写路径使用行级锁，能有效防止同实例并发双写。
  - Redis + NATS 架构已具备多实例扩展基础。
- **主要风险**：
  - 热点用户的高频写会集中竞争同一用户的仓库行与实例数据。
  - 若客户端重试策略不当，版本冲突会形成“重试风暴”。
  - 缺少针对库存链路的集中冲突指标，问题发现可能滞后。

## 本期已落地改进
- 角色页改为仓库实例按需读取，移除批量逐实例元信息拉取，降低高频读放大。
- 引入统一物品详情弹窗，改为按需加载单个实例详情与操作信息，减少 N+1 读取压力。
- 限流改为 Redis 固定窗口共享计数，降低多实例下异常请求对库存写链路的冲击。
- 市场主链路（上架/购买/求购成交/撤销/下架）新增仓库变动日志写入，覆盖金币与物品的正常在线流转。
- 商店买卖、拍卖（创建/竞价/成交/过期返还/撤销）、回收链路补齐仓库变动日志。
- 动作队列结算的仓库日志不再仅限离线快进，在线结算同样写入消耗/产出记录（包含强化消耗）。
- 战斗房间入场消耗、结算奖励、打断奖励、每日任务提交消耗/奖励、词缀拆附魔消耗等在线链路已纳入仓库日志。
- 新增 `inventory_ledger.go` 作为库存写门面：业务层通过统一 `LedgerConsume* / LedgerGrant* / LedgerSetState* / LedgerTransfer*` 接口执行库存变更并自动落仓库日志，避免分散拼装日志。
- 仓库日志升级为库存审计旁路：`Ledger*` 只生成标准化审计事件，事务提交后再写入 `player_warehouse_change_logs`；日志失败只记录服务端错误，不回滚库存真值。
- 新增守护测试 `inventory_ledger_guardrail_test.go`，禁止业务文件直接调用 `insertWarehouseChangeLogTx`，强制归口到库存门面。
- 动作队列新增“实例材料绑定”能力：可在 action args 指定 `materialInstanceBindings` 进行实例级扣减。若绑定实例存在 affix 则拒绝执行；失败返回通用参数错误码，不回传具体实例信息。

## 限流状态存储与手工重置（SOP）
- 键前缀：
  - `ratelimit:api:{ip}`
  - `ratelimit:register:{ip}`
  - `ratelimit:login:{ip}`
  - `ratelimit:login-attempt:fail:{ip}:{username}`
  - `ratelimit:login-attempt:lock:{ip}:{username}`
- 重置策略：按最小范围删除目标 key（优先单用户/单 IP），避免全量清空。
- 风险提示：批量删除会短时放宽防护，建议在低峰执行并配合监控观察。

# 灌注容量突破

当前版本见 [三档灌注容量料理](alchemy-capacity-tiers.md)。本页保留 V6/V3 的历史规则与兼容说明；新制作采用 7% 起步和分档上限。

## V6/V3 历史规则

当前模板为苔火 V6、霜月 V3（`food-capacity-risk-v1`）。容量沿用下述突破规则；新增成功率代价见「成功率代价」。前版 V5/V2 继续用于已冻结成品与效果的兼容。

不改动原稳定性曲线。无料理容量逐渐趋近于 `unitBasis * maxBasisMultiplier * 32`，这是单种素材的理论上界，不是所有槽位共用的总量；有限稳定性下通常略低，还受投入基数对齐和库存影响。

| 当前素材档位 | 无料理理论上界 | 标准料理 10% 后 | 顶配料理 17% 后 |
| --- | ---: | ---: | ---: |
| 神话：基础 50、基数 5 | 1600 | 1760 | 1870 |
| 传说：基础 100、基数 4 | 3200 | 3520 | 3744 |
| 传说：基础 120、基数 4 | 3840 | 4224 | 4492 |
| 传说：基础 200、基数 4 | 6400 | 7040 | 7488 |

传说基础 100：`holy_cat_royal_jewel`、`parade_king_medal`；基础 120：`shadow_paw_master_sigil`、`timekeeper_core`、`final_volume_key_sigil`；基础 200：`moonwood`、`moonvine_fiber`、`moon_resin`、`moon_dew`、`crystal_chunk`、`moonwood_blank`、`crystal`、`lunar_veil`。神话为当前六种灌注素材。

苔火仅匹配普通至史诗，霜月仅匹配传说、神话。对每种材料分别计算：

```text
B = 不含料理时的当前容量（已包含稳定性）
F = 冻结的固定容量额度
R = 冻结的比例额度，最高 0.17
额外容量 = min(max(F, floor(B * R)), B * 2)
最终容量 = 按该材料投入基数向下对齐(B + 额外容量)
当前可选数量 = min(最终容量, 按基数对齐的库存)
```

固定额与比例额取高，不相加；前期固定额保留价值，后期比例额避免固定 +25/+50 被稳定性稀释。10%～17% 指极限阶段的容量提升，不是所有阶段只能提升这个比例，也不是最终随机属性保证提高相同比例。仍需真实支付全部额外材料，原成功率、损耗、组合、同源限制和精度规则保留。

## 食材与成本

新参数 `quantityLimitBonusRate` 基础 10%；沿用具体食材线性评分，长度系数 0.10、同长度体重系数 0.20、特质系数 0.10，最终限制在 10%～17%。先应用现有特殊变异乘数，再截断至 17%。三种变异唯一集合乘数仍为 `1.50 * 1.10 * 1.10 = 1.815`，不会按鱼的尾数重复计算。

固定额度保持既有成长：苔火烤鱼 +50 至变异前 +200，鱼汤 +45 至 +180；三变异顶配分别 +363/+327。霜月烤鱼和鱼汤均为 +25 至变异前 +50，三变异顶配 +91。每个参数独立计分，比例额度封顶不会截掉固定额度的成长。

霜月两道料理均消耗月镜鲤、霜幕鲟各一尾，月露 24、瓶装星光 12；烤鱼另需煤炭 2，鱼汤另需晨露 3。两项辅料从 6/3 提高到 24/12，按当前模板基础价值计由 936 增至 3744（不含鱼与燃料，不是市场成交价）。苔火辅料不变。次数、时长、棱彩次数奖励、彩虹时间奖励及同组互斥规则不变。

## 成功率代价

| 料理 | 标准成功率降低 | 具体食材允许范围 | 顶配三变异 |
| --- | ---: | ---: | ---: |
| 苔火烤鱼 | 4% | 2%～6% | 2% |
| 苔火鱼汤 | 3% | 2%～5% | 2% |
| 霜月烤鱼 | 6% | 3%～9% | 3% |
| 霜月鱼汤 | 5% | 3%～8% | 3% |

`successRatePenalty` 为可选参数，历史缺省为 0。范围是配置保护边界，不表示当前食材一定能触及两端；用长度 0.15、同长度体重 0.05、特质 0.05 系数和原有特殊变异乘数，按反比减轻代价，再截断到各自边界。闪光在其他变异和优秀体型并存时仍有额外作用。

先完成原有等级、用量、稳定性、介质的失败率计算，再加一次料理失败风险；最后继续遵守介质的成功率保底及概率 [0,1] 边界。并非降低稳定性，也不会把代价再除以稳定性。两种有效料理混合灌注时相加，不按槽位重复；处理器总上限为 20%。未匹配实际素材时，不扣次数、不给容量、也不增加失败风险。

例如无料理成功率 92%，标准霜月烤鱼后为 86%；无料理成功率 100% 时为 94%。若介质保底限制了实际降幅，界面显示保底后的实际差值。灌注成功率标签旁显示料理代价，概率详情列出失败风险；普通配方与组合配方使用同一个修正函数，概率采样次数不变。

## 权威与兼容

- 容量突破初版引用苔火 V5、霜月 V2，`rulesetVersion=food-capacity-breakthrough-v1`；风险版引用 V6/V3。旧效果定义不删除，前版 ID 加入配方 `legacyEffectIds`。
- 服务端处理器严格校验可选比例参数。历史定制成品、已生效旧效果、已开始动作的快照缺少该参数时为 0，不暗中重算旧数值。普通模板物品按当前模板食用。
- 动作开始时确定实际有效的料理及次数；服务端数量校验、制作与持久化炼金印记、竞技场合法性校验共用容量处理器。继续复用在线/离线动作快照，不新建结算入口或扫描历史队列。
- 前端共享 composable 折叠相同参数；灌注数量输入框、实际增加额度和理论上界前后对比共用容量计算。缓存刷新、到期或次数耗尽会恢复无料理限制；库存不足仍限制输入，不能靠界面声明超额投入。
- 概率文案显示 `+8%`，计算仍是直接增加概率，不改为相对乘法。全局面板默认折叠，移除料理描述、冗长规则和重复受益说明，保留数值、余量、业务类别及受益对象；工具栏计数徽标固定正圆。

## 验证与部署

回归覆盖比例边界、固定/比例取高、稀有度隔离、神话基数对齐、无料理拒绝超额、冻结印记与旧参数、真实灌注组件缓存失效、文案和折叠状态。以极高但有限的稳定性验证月华木当前容量 6396 → 7480，确实超过原理论上界 6400；理论显示为 6400 → 7488，二者不混称。

本次不增加数据库结构或查询。发布需同步生成数据、服务端/动作执行进程与前端；不要先独立上线新参数的数据到只认识旧参数的进程。回滚必须保留新效果与印记解析兼容能力，不能直接将已生成的新定制物品交给不认识比例参数的旧服务端。

浏览器检查使用真实组件与隔离状态，不是登录账号的端到端生产验证；数据库事务测试需要独立 PostgreSQL 测试环境。尚未进行线上经济验证，不能据此承诺零风险。

# 邮箱域名策略

## 目标

邮箱验证码只能确认邮箱当前可收信，不能识别临时邮箱。本策略在服务端阻止已确认的临时邮箱域名进入新的账号绑定流程，同时不改变现有账号、找回密码和登录行为。

## 配置与名单

- 运行参数位于 `packages/game-config/source/global-config.json` 的 `emailDomainPolicy`。
- 默认名单位于 `packages/game-config/source/disposable-email-domains.txt`，每行一个域名。
- `EMAIL_DOMAIN_BLOCKLIST_PATH` 可以覆盖名单路径，便于不同部署环境维护独立文件。
- `blockedDomains` 用于少量内联规则，`allowedDomains` 优先于所有拦截规则，可处理误报。
- 修改配置或名单后需要重启服务端；请求链路不会访问外部邮箱检测服务。

域名规则使用小写与 Punycode 规范化。规则 `pugb.vip` 同时匹配 `pugb.vip` 和 `mail.pugb.vip`，但不会匹配 `notpugb.vip`。
配置会拒绝 `com`、`co.uk` 这类公共后缀，避免一次误配置影响大批正常邮箱。

## 生效入口

策略只保护会创建或改变邮箱归属的入口：

- 注册账号
- 发送邮箱绑定验证码
- 确认邮箱绑定验证码
- 直接修改邮箱接口

直接修改邮箱时会清除旧邮箱的验证状态，避免更换地址后继续沿用之前的验证结果。

找回密码仍允许已有账号使用原邮箱，避免部署新名单后造成账号找回回归。系统也不会自动删除、封禁或修改已经使用名单域名的账号。

## 名单维护

仅将已经人工确认可批量生成、短期回收或公开共享收件箱的域名加入默认名单。社区名单可以先导入独立部署文件观察命中情况，再逐步合并；不要未经审核直接覆盖默认名单。
